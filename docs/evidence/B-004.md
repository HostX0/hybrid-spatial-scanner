# B-004 evidence — owned ARSession spike and effective configuration

## Delivered

`HSSApp/ARSessionCoordinator.swift` adds one main-actor coordinator and one
production `SystemARSessionDriver`. The driver creates exactly one `ARSession`,
is its only configuration owner, installs one delegate, and clears the delegate
and pauses the session on explicit stop and driver deinitialization. Repeated
start requests do not run another configuration. No second camera session,
coordinate merge, simulated frame, or geometry is created.

Camera permission is inspected at initialization but requested only from the
explicit **Allow Camera** action. The requested `sceneDepth` plus `.mesh`
configuration runs only when the B-003 readiness result and current ARKit
capability inspection both approve it. The driver reads back
`ARSession.configuration` and returns the effective depth semantic and mesh
option. The coordinator records requested, supported, and chosen features,
world-tracking support, RoomPlan state, reduced-proposal state, and a fallback
reason.

If required support is absent, the effective configuration differs, or the
requested run fails initially or at runtime, the same owned driver attempts a
plain world-tracking ARKit fallback with no depth semantic and no mesh. The UI
labels this as reduced-proposal fallback and does not claim metric readiness
until tracking becomes normal. Limited tracking, interruption, relocalization,
failure, stop, and restart state are modeled through injected events.

RoomPlan is **not enabled**. Its report value is
`notEnabledPendingPhysicalValidation`; this is a provisional path, not evidence
of shared-session compatibility or RoomPlan output.

Observed: `** TEST SUCCEEDED **`; 13 tests executed with 0 failures. Eight new

permission, supported configuration/reporting, unsupported fallback, failed
configuration fallback on the same driver, tracking readiness, and stop/delegate

The first strict-concurrency build failed because a main-actor driver deinit
accessed ARKit's legacy non-Sendable `ARSession`. The repair uses
`@preconcurrency import ARKit` while retaining synchronous pause/delegate
cleanup; the subsequent build and tests passed. The remaining build warnings
were Xcode's unrelated “no AppIntents.framework dependency found” metadata
messages.

## What simulator evidence does and does not establish

The simulator verifies Swift state transitions, dependency seams, permission
request ownership, requested/effective report construction, fallback selection,
single-driver behavior, and explicit stop cleanup. It has no LiDAR/camera proof
and does not establish `sceneDepth`, mesh callbacks, calibration, orientation,
RoomPlan coexistence, recovery fidelity, frame timing, power, or thermal behavior.
