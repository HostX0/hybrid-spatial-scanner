# B-039 evidence — portable project import validation foundation

## Delivered contract

`ProjectImportValidation` is an additive portable C++ archive-boundary module.
It accepts archive entries only through caller-supplied metadata and injected
`StreamingReader` instances; it neither parses ZIP containers, extracts files,
writes a project directory, nor commits a manifest. This preserves the
separation between hostile-input validation and future platform archive and
durable-store integrations.

The validator requires strict canonical, relative, slash-separated paths. It
rejects absolute paths, drive prefixes, NULs, backslashes, empty components and
dot segments. It detects canonicalization collisions before any stream is
read. Symbolic and hard-link entries are unsupported. Regular entries require
a declared uncompressed length, SHA-256 digest, and reader; directory metadata
must be empty.

Before calling a reader, the module applies the D16 baseline envelope: 20,000
files, 8 GiB expanded bytes, 256 MiB binary/other entry bytes, 16 MiB JSON
entry bytes, and 4096 path bytes. Length accounting is checked for overflow.
Streams are consumed in a fixed 64 KiB buffer, then require exact EOF and a
matching SHA-256. The validation result contains accepted paths only if every
entry succeeds, so it provides no partial publication signal to a future
extractor/committer.

## Limits and follow-up

This does not claim native ZIP parsing, ZIP interoperability, archive metadata
fidelity, filesystem extraction safety, atomic manifest commit, iOS protected
data behavior, simulator coverage, physical-device coverage, or hardware
capture evidence. A future archive adapter must enumerate untrusted archive
metadata into this interface and extract only after a successful result; a
future durable-store integration must separately perform D16 manifest-last
commit and recovery.
