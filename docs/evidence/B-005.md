## Scope and contract

This change adds a bounded Swift adapter/normalizer from the existing, single
`ARSession` driver's `ARFrame` callback. It does not create another session,
change `include/hss/hss_api.h`, change a JSON schema, or create geometry.

The implementation was checked against `docs/D15_Engine.md` sections 3–5,
`docs/D14_Research.md`, `docs/D16_Contracts.md`, `docs/D17_UX_Delivery.md`, and
the coordinate/frame requirements in
`docs/baseline/02_Native Architecture Capture_and_Contracts_D03–D05.txt`.
There is no `docs/D14_CoordinateFrames.md` file in baseline commit `c7f6e72`;
the named coordinate requirements are present in the files above.

The normalized contract is:

- `ARFrame.sceneDepth` is the sole measurement input. The adapter has no
  `smoothedSceneDepth` input, so it cannot silently substitute or double-count it.
- Intrinsics are scaled from their calibrated sensor-image dimensions through
  an explicit sensor-image crop into the actual depth dimensions. The ARKit
  adapter records a full-sensor crop; synthetic/replay inputs can state another
  crop. No UI orientation or viewport transform participates in calibration.
- Every accepted result owns copied Swift arrays. A CV pixel-buffer base address
  exists only inside one read-only lock closure and unlock is guaranteed with
  `defer`. RGB/depth/confidence dimensions, pixel formats, plane strides,
  column-major `T_world_camera`, epoch, sequence, and monotonic timestamp are
  retained in the result.
- A frame is bounded to 307,200 depth samples by default. A single-slot mailbox
  replaces an expendable pending normalized frame under MainActor backpressure.
- Non-finite and non-positive depth samples are masked and counted separately;
  frames with no valid depth are rejected. Tracking, timestamp, calibration,
  rigid pose, RGB/depth/confidence layout/stride, size budget, and buffer access
  have explicit frame-rejection reasons and counters.
- Optional confidence is copied as ordinal data. Missing confidence is `255`,
  distinct from depth validity. ARKit low confidence is excluded from
  `metricFusionMask` but remains in `provisionalPreviewMask`.

## Synthetic coverage

`tests/SceneDepthIngestionTests.swift` exercises:

- intrinsics scaling through an explicit crop without presentation rotation;
- padded depth and confidence strides;
- non-finite/non-positive sample masking and counters;
- low-confidence metric exclusion and provisional preview eligibility;
- unavailable confidence (`255`) independent of valid depth;
- tracking, calibration, pose, stride/layout, confidence-size, and sample-budget rejection;
- balanced lock/unlock and copy ownership after source mutation; and
- latest-frame replacement in the bounded single-slot mailbox.

The existing B-003/B-004 tests also remain enabled. The final simulator run
executed 21 tests: 13 existing application/session tests plus 8 B-005 tests.

## Hardware limits and next prerequisite

The iOS simulator supplies no LiDAR `sceneDepth`, so it cannot prove the actual
ARFrame buffer relationship. On an iPhone 15 Pro Max, ENG-02 must still record
and verify:

- real `sceneDepth` availability, depth/RGB dimensions, pixel formats, and strides;
- actual camera-intrinsics reference dimensions and the RGB/depth crop/alignment relationship;
- the axial-depth optical-to-ARKit convention against a measured physical plane,
  including off-axis pixels rather than only the principal point;
- stable sensor-coordinate behavior across portrait/landscape UI changes, with
  no double rotation and no viewport-transform calibration; and
- invalid/limited tracking, interruption, epoch assignment, confidence behavior,
  and effective session configuration on the physical device.

Therefore these synthetic and simulator results validate calculations,
rejection, stride handling, bounded ownership, and target integration only.
They are not physical metrology or LiDAR evidence and do not by themselves close
the backlog acceptance statement “survives orientation tests.”

The next implementation prerequisite for retained deterministic replay is B-006
(mesh anchor update/removal) followed by B-007 (chunked checkpoint storage),
while the B-005 hardware gate remains the iPhone 15 Pro Max ENG-02 capture above.
