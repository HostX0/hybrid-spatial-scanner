# B-014 evidence — ABI bounds and malformed native inputs

## Delivered

`SpatialCore/src/hss_engine.cpp` now distinguishes unsupported enum/reserved
values (`HSS_INVALID_ARGUMENT`) from invalid rigid transforms
(`HSS_INVALID_COORDINATE_FRAME`), rejects nonzero `HSSFrame.reserved`, and
retains the existing rejection of nonzero configuration flags.  Command and
room-proposal byte views enforce the D16 initial 16 MiB JSON-record bound before
copying, so an oversized claimed length is rejected without dereferencing its
data pointer.  The C facade remains exception-contained.

`tests/hss_engine_contract_test.cpp` adds allocated extended-message fixtures:
zero trailing bytes are accepted and a nonzero trailing byte is rejected.  It
also exercises undersized layouts, ABI mismatch, null/length disagreement,
unsupported flags/enums, depth stride and addressed-range overflow, mesh byte
count overflow, JSON bounds, cleared failure outputs, and no-partial-write
copy-out behavior.  No test claims that a length field makes arbitrary caller
memory safe; extension tests allocate the full described message explicitly.
