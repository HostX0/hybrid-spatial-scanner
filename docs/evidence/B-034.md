# B-034 — deterministic DXF metre/layer exporter

## Implemented host module

`hss_dxf_exporter` adds a portable AC1015 ASCII DXF serializer for one frozen
plan snapshot. It declares `$INSUNITS=6`, writes model-space coordinates in
metres (`X=U`, `Y=V`), and emits caller-supplied segments/contours as
`LWPOLYLINE` without joining, closing, offsetting, simplifying, or creating
missing geometry. The accepted layers are `HSS_BOUNDARY`, `HSS_FIXED`,
`HSS_OPENINGS`, `HSS_FURNITURE`, `HSS_OVERHEAD`, `HSS_DIMS`, `HSS_LABELS`, and
`HSS_WARNINGS`.

Every primitive names retained B-031 fragment/support lineage and the same
frozen scene revision as the B-032 annotation layout. Unknown and inferred
primitives are emitted on `HSS_WARNINGS`; their exact supplied vertices remain
in the companion deterministic UTF-8 JSON along with requested layer,
provenance, source IDs, plan fragment states, plan quality, cut height, source
synthetic flag, warning strings, and annotation availability/value. Unknown or
inferred annotations emit no metric value. Non-ASCII text is retained in that
sidecar and omitted from AC1015 `TEXT`, whose code page portability is not
asserted.

Executed from this B-034 worktree (the current shell does not expose the
recorded `cmake` executable, so this is an equivalent focused direct compile):

```text
clang++ -std=c++20 -Wall -Wextra -Werror -Wpedantic \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  -ISpatialCore/include SpatialCore/src/dxf_exporter.cpp \
  tests/hss_dxf_exporter_test.cpp -o build-b034-asan/hss_dxf_exporter_test
./build-b034-asan/hss_dxf_exporter_test
```

The focused test passed. It checks AC1015/metre declaration, standard layers,
one-metre geometry, explicit closed-contour flags, deterministic output under
permuted input, retained source/unknown metadata, UTF-8 Arabic sidecar policy,
and rejection of stale or unprovenanced geometry.

## Limits and next dependency

This is a portable serializer only. It does not write an export transaction,
hash/commit a bundle, import into an external CAD consumer, run on iOS, or
establish capture or physical accuracy. It intentionally requires the future
frozen snapshot adapter to submit exact export primitives and connect the
returned DXF/sidecar to storage/export records. TC-034 still requires the
declared independent CAD-consumer checks.
