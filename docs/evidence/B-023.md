## Delivered standalone contract module

`hss::command::RevisionedCommandGate` is an additive C++20 module. It accepts
already syntax/schema/variant-validated command metadata together with the exact
UTF-8 command bytes from which that metadata was parsed. The module deliberately
does not parse, reserialize, normalize, or canonicalize JSON.

For a new command ID, the gate validates bounded UTF-8 bytes, canonical uint64
decimal revision/event strings, canonical lowercase non-nil UUIDs, project
identity, expected scene revision, unique current target identities, and target
lineage before invoking the supplied operation. Stale reconciliation is off by
default. A caller may enable it only for a command contract that explicitly
allows reconciliation, and then every target must still be current with no
lineage change after the command's expected revision. A stale targetless command
is rejected because unchanged lineage cannot be proven by this module.

Application runs against a copy of the last accepted `SceneState`. An applied
candidate is published only if it preserves project identity, remains a valid
bounded scene, and advances exactly one revision. A stale, future, wrong-project,
non-current-target, changed-lineage, rejected, conflicting, throwing, or invalid
candidate cannot replace the prior accepted state. Conflict and rejected results
are still retained so a byte-identical retry is deterministic.

The volatile record retains the exact command bytes, their SHA-256 digest, the
exact opaque result bytes, outcome, and associated scene revision. An identical
command-ID/byte retry returns the recorded result without invoking application.
The same ID with any different bytes returns `duplicate_mismatch`, including the
synthetic fixture pair whose parsed JSON values are equivalent but whitespace
and final-byte layout differ.

All returned submissions set `durably_committed` to false. The result fixture
uses `durability: not_committed` and a null journal commit ID. This module has no
journal, filesystem, manifest, fsync, recovery, or save/reopen implementation.

## Scope and limitations

This task changes no C ABI, JSON schema, facade engine, persistence/storage
module, Swift/Xcode source, command variant semantics, solver, or geometry. The
new C++ interface is standalone and not wired into `SpatialCore` or the native
application. The caller remains responsible for proving that supplied metadata
was parsed from the same exact bytes after schema and variant-semantic
validation, and for serializing gate ownership.

The in-memory records are not durable and deliberately make no Saved or crash
recovery claim. No iPhone/simulator build, ARKit/RoomPlan session, physical
device run, sensor capture, metrology, performance/thermal measurement,
save/reopen, or crash-recovery test ran. Synthetic host fixtures and sanitizer
checks are software-contract evidence only, not evidence of physical accuracy
or production scanner completion.
