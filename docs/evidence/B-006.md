# B-006 evidence — ARMeshAnchor lifecycle adapter

## Delivered contract

`ARMeshAnchorLifecycleAdapter` reads each ARKit mesh buffer synchronously during
the B-004 owned `ARSessionDelegate` callback. It copies vertices, normals,
triangle indices and optional per-face classification into `MeshAnchorPayload`;
the retained payload has no `ARMeshAnchor`, `ARGeometrySource`, `MTLBuffer`, or
borrowed pointer. It derives and retains local bounds, and retains the
column-major `T_world_anchor`, session epoch, event sequence, and monotonic
time on every accepted revision.

`MeshAnchorLifecycleStore` is the narrow, synthetic-testable lifecycle
protocol. A UUID is the only identity key: it never associates anchors by
position. Add creates revision 1; update atomically replaces the full prior
payload and advances its revision; remove deletes the live value; a later add
of the same UUID begins a new generation. No prior payload remains live after a
remove or replacement.

The store rejects and counts invalid timestamps, non-rigid/nonfinite transforms,
non-monotonic per-epoch sequences, absent/unexpected payloads, invalid lifecycle
transitions, allocation budgets, nonfinite vertex/normal data, mismatched
normals/classifications, invalid bounds and malformed/out-of-range indices.
Rejected updates leave the previously accepted revision untouched. Empty or
malformed platform geometry is rejected rather than turned into measured
geometry. The implementation does not alter `hss_api.h`, schemas, SceneDepth
ingestion, or ARSession ownership; B-004's one driver remains the only session
and delegate owner.

## Synthetic verification

`tests/MeshAnchorLifecycleTests.swift` covers add → update → remove, whole
payload replacement (including a deliberately distant replacement), UUID
re-add generation, stale sequence rejection, invalid indices/transforms, counter
reasons, and source mutation after ingestion. These tests use only synthetic
Swift values; they do **not** prove ARKit's runtime mesh layout or sensor output.
The source payload's vertices are mutable only while assembling input; the test
mutates that source after `apply` and verifies that both accepted copies remain
unchanged.

`plutil -lint HSSApp/HybridSpatialScanner.xcodeproj/project.pbxproj` passes.
The generic iOS Simulator build was invoked with the project target and a
workspace-local DerivedData path. The B-006 Swift sources compiled after fixing
the ARGeometryElement layout to use its documented buffer start (it has no
offset property). The final build could not complete because this sandbox cannot
run Xcode's Preview macro plugin (`sandbox-exec: Operation not permitted`) in
the pre-existing `ReadinessView.swift`. This is unrelated to the mesh adapter.
`cmake` is not installed in this environment, so CMake/CTest could not run.
CoreSimulatorService is unavailable, so neither the requested iPhone 18 Pro
simulator selection nor `xcodebuild test` execution was possible.

## Required hardware validation — iPhone 15 Pro Max

This evidence makes no hardware or metrology claim. On an iPhone 15 Pro Max
with a single B-004-owned session configured for `.sceneDepth` and `.mesh`:

1. Record effective configuration, session identity, capture epoch, event
   sequence, and the count/reasons shown by the lifecycle store.
2. Capture a static wall while moving enough to observe repeated mesh updates;
   verify every update replaces, not accumulates, the matching UUID payload.
3. Walk a previously captured area out of reconstruction range and verify remove
   clears its live revision; return and verify any re-add has a new generation.
4. Trigger relocalization/tracking reset; verify a new epoch is recorded and no
   geometry is merged across epochs without the separately accepted relation.
5. Preserve logs plus the selected source chunks and inspect all copied bounds,
   indices and transforms. Report unsupported/malformed layouts as rejection,
   not as geometry.

Hardware results, sensor fidelity, RoomPlan coexistence, and delivery to the C
engine remain unproven prerequisites; a later bridge owner must map accepted
owned revisions to the existing C mesh-event contract without changing this
lifecycle ownership rule.
