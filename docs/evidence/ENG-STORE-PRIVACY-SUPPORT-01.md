request/time fields. Its normalized inspected template hash is
`00fbcbe2273ca54d0d2943e77636ef2d4f88b8502cba984b29734af003fd5862`.
The checker only accepts this complete reviewed suffix, not arbitrary scripts,
and rejects product-byte, CSS or host-template changes. Hosting processing is
disclosed separately from app-local capture. Generated source has no JavaScript;
no assertion that live hosting has no scripts/cookies is made. Source CSP is
restrictive. Script execution/cookie behavior and visual browser QA were not
tested. Mobile Safari and desktop Chrome user-agent HTTP requests returned the
real support page; these are **not** actual browser interactions.

Retained failed tooling attempts are not scanner defects or hidden successes:

- Initial release checker incorrectly required an unused UserDefaults category;
  `store-preparation-source-20261011` failed. The checker was corrected to the
  actual SystemBootTime, DiskSpace and FileTimestamp inventory, without changing
  application privacy declarations. `store-preparation-validated-20261011`
  passed eight then-authored regressions; the final ninth covers hosted bytes.
- The first Site helper was launched in the HSS checkout. An empty stdin request
  rejected credentials before any source/publication change; the open remote
  stdin caused a bounded timeout. Correct Site cwd and a closed one-request
  in-memory pipe then succeeded in `store-site-hidden-stdin-20261011`.
  Two overlapping attempts correctly refused the already-owned original flock.
- `store-site-public-https-20261011` used the wrong checker CLI option, exited 2
  before HTTP requests, and was replaced by a new preserved successful job.
- A default Python urllib user-agent diagnostic received HTTP 403; the explicit
  page checker and ordinary mobile/desktop browser user-agent requests returned
  200 without credentials. No private access restriction was removed or bypassed.
- A staging-helper syntax error and unmatched local patch contexts were corrected
  before affected execution/editing. Their failures do not count as product tests.

The Sites helper's transient credential stayed in session memory/stdin; no
