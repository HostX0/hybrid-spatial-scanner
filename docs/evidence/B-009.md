# B-009 evidence — C facade and Swift ownership bridge

## Delivered

`SpatialCore/src/hss_engine.cpp` implements every declaration in the normative
`include/hss/hss_api.h` without changing that header. The portable facade is a
single-owner mutable engine with synchronous staging copies for accepted input
buffers, explicit validation/status mapping, no exception escape across C
linkage, safe nullable release calls, and immutable independently-owned
snapshots. Snapshot copy-out uses the required two-call protocol: insufficient
capacity reports the full count and writes no partial bytes/elements.

The current snapshot is a schema-shaped, zero-geometry, provisional scene. It
can outlive its engine, but it is deliberately **not scanner output**: this task
does not add ARKit, RoomPlan, capture, dense fusion, reconstruction, persistence
or UI scanning behavior. Valid frame, mesh, room-proposal, and command inputs
are synchronously copied into bounded staging storage and then return
`HSS_UNSUPPORTED_CAPABILITY` because those processing backends are not present.

`HSSApp/HSSBridge.swift` adds an `HSSEngineOwner` actor and a `@MainActor final`
`HSSSnapshotLease`. The lease adopts exactly one acquired C snapshot handle,
releases it in `deinit`, and exposes no owning raw pointer. It does not use
`@unchecked Sendable`; its main-actor isolation keeps pointer use on a selected
executor.

## Native project wiring verification (2026-09-22)

The Xcode project now includes `SpatialCore/src/hss_engine.cpp` in the
`SpatialCore` static-library target and `HSSApp/HSSBridge.swift` in the app
target. The app and test targets search the existing `include/module.modulemap`
for the `HSSContracts` C module; the app target links `libc++` for the C++ core.

The Swift 6/iOS 17 build surfaced that actor/global-actor deinits cannot read a
stored non-Sendable `OpaquePointer`. The bridge retains the same private owned
handle but stores its address as a private `UInt`, reconstructing the opaque
pointer only at C call boundaries and in `deinit`. This avoids both unsafe
sendability annotations and iOS-18.4-only isolated deinits. Snapshot adoption
therefore transfers a `UInt` address to the main-actor final lease, while the
lease remains the sole releasing owner.

The following native simulator checks passed with Xcode 27.0 (27A266a), using
the iPhone 18 Pro simulator on iOS 27.0 and `CODE_SIGNING_ALLOWED=NO`:
