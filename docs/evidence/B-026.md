# B-026 evidence — bounded quality-to-guidance policy

Date: 2026-09-22

Branch: `hss/b026-guidance-policy`

Baseline: `3b838fb`

## Delivered contract

`hss::guidance::evaluate` is a standalone C++20 policy module. It consumes a
bounded, caller-measured quality vector and returns at most one actionable
issue. Every issued item carries the source evidence revision and expires at
the next quality revision. The policy does not estimate geometry, create
measurements, operate a camera, schedule work, render an overlay, or trigger a
haptic device.

Tracking/relocalization and resource validity are evaluated before conflict and
completeness conditions. An unresolved relocalization or any non-normal
tracking state yields `kStabilizeTracking` and marks precise overlays hidden;
it never freezes a stale precision marker. Coverage is considered only when a
caller supplies a nonzero target-domain revision. Occlusion selects a
feature-side observation action, low diversity selects another viewpoint, and
processing-pending is the only waiting issue. No output contains a timing,
distance, clearance, collision-free-navigation, or sensor-accuracy claim.

The caller supplies all debounce, minimum-display, repeated-haptic-suppression,
and hysteresis values in `Tuning`. No policy default silently becomes a UI or
engine timing contract. Critical tracking loss bypasses the supplied noncritical
debounce. Inputs reject nonfinite values, invalid enum values, out-of-range
normalized values, invalid hysteresis ordering, nonmonotonic revisions, and
invalid state timestamps. Failures return the exact prior state and no partial
issue.

This is additive only: no Swift/app UI, scanner engine, C ABI, JSON schema,
replay, durable storage, or geometry module changes.

## Focused host verification

`hss_guidance_policy_test` covers resource-over-completeness priority,
relocalization precision suppression, evidence revision and expiry, caller
debounce/hysteresis, pending-processing-only waiting, an occlusion-specific
action, nonfinite input, and atomic invalid-tuning rejection. The small
`fixtures/guidance_policy/quality_cases.txt` fixture documents bounded policy
examples without posing as capture or device evidence.

Run from the repository root:

```sh
cmake -S . -B /tmp/hss-b026-build -DHSS_ENABLE_SANITIZERS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/hss-b026-build --parallel
ctest --test-dir /tmp/hss-b026-build --output-on-failure
git diff --check
```

Observed: AppleClang 21.0.0.21000334 configured and built successfully; CTest
passed 15/15 under ASan/UBSan, including `hss_guidance_policy`; and `git diff
--check` exited 0 with no output. ASan/UBSan are host memory/undefined-behavior
checks only; they are not device UX, timing, relocalization, LiDAR, metrology,
or physical-navigation evidence.

## Hardware and integration limits

No simulator or physical-device test ran. In particular, this work makes no
claim about haptic behavior, overlay presentation, response latency, depth
quality, tracking recovery, distance, calibration, or collision safety. A
future owner must connect measured quality facts and a declared tuning profile
at the UI/engine seam, then verify the actual device behavior and preserve the
issue evidence revision in its audit trail.
