## Delivered contract

`hss::resource::ResourcePolicy` is an additive, owner-serialized C++20 state
machine. It consumes ordered explicit thermal, memory-pressure and free-storage
measurements. Each sensor carries a separate measured/unmeasured status; an
unmeasured value is never interpreted as a measured nominal state and cannot
clear a latched pressure condition.

The default storage stop, warning and recovery reserves are provisional tuning
inputs (512 MiB, 1 GiB and 1.5 GiB). Configuration requires strictly ordered,
nonzero reserves, caps them at 16 TiB, and bounds recovery hysteresis at 1–1024
complete samples. Samples require a nonzero increasing sequence, finite
nonnegative monotonic time, valid enum ranges, and canonical placeholders for
unmeasured sensors. Invalid and out-of-order samples return explicit status and
reason without changing pressure state.

The deterministic policy modes are:

- `kNormal`: metric and optional work may proceed.
- `kConserving`: preview quality, optional appearance and unprotected display
  LOD are reduced or deferred while metric validity checks remain enabled.
- `kCheckpointPending`: unsafe pressure stops new metric intake, retains
  existing sources, and requests one explicit durable checkpoint.
- `kPaused`: checkpoint success or failure is explicit and capture remains
  paused until the configured number of complete clear samples is observed.

Thermal fair/serious, memory warning and the storage warning reserve enter
conservation. Thermal critical, memory critical and the inclusive storage stop
reserve enter checkpoint-pending. Recovery requires every sensor to be
measured, thermal/memory nominal, storage at or above the recovery reserve, and
the configured consecutive sample count. A clear reading cannot substitute for
the B-038 checkpoint completion handshake.

The event decision surface preserves the B-013/D15 protected path. Commands,
epoch transitions, mesh removals and durable commit completions always return
`kAcceptProtected`, including while checkpointing or paused. Preview work can
be dropped, optional appearance/display work can be deferred, and unsafe metric
input returns `kRetainSourceAndPauseCapture`. There is no source-eviction
action. Saturating counters record accepted/rejected/unmeasured samples,
constrained/unsafe observations, pressure escalation/recovery, checkpoint
results, dropped preview events, deferred optional work, source-pause events
and protected-event acceptance.

- bounded configuration and finite/range/sample-order validation with atomic
  rejection;
- unmeasured sensor status remaining distinct from measured nominal state;
- nominal to conserving to checkpoint-pending to paused transitions;
- explicit successful and failed checkpoint outcomes;
- storage threshold inclusivity plus byte and consecutive-sample hysteresis;
- optional-work degradation while validity checks remain enabled;
- source retention and paused metric intake at unsafe pressure;
- protected command, epoch, mesh-removal and durable-commit policy; and

## Interface and evidence limits

Changed files are the new portable header/source, one focused host test, this
evidence file, and additive CMake source/test registration. There is no C ABI,
JSON schema, ingress, recovery/store, engine, Swift/app, Xcode project, or
persisted-format change. The state machine does not query device APIs, perform
checkpoint I/O, delete/evict source data, schedule workers, or claim that a
checkpoint succeeded; platform owners must supply measured values and explicit
checkpoint results.

No iPhone or physical-device test was run. Host tests do not verify real iOS
thermal notifications, memory-pressure delivery, available-capacity semantics,
APFS/protected-data behavior, backgrounding, phone lock, low-storage writes,
Metal cancellation, battery/endurance behavior, source-retention wiring, or
the provisional threshold values. Those ENG-05/ENG-12 and B-047 checks remain
open and require declared-device evidence.
