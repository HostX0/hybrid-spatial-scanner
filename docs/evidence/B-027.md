# B-027 — Pending target tools

## Scope

This portable-core slice implements the target selection and protrusion-tool
preconditions behind TC-027. It is deliberately not an iOS reticle, ARKit
raycast, renderer, command adapter, or durable-journal implementation.

`Target` preserves the selection's scene revision and provenance. An
unsupported no-depth tap is a `kPending` target with `pending_no_depth`
provenance, no project-space coordinate and no support IDs. The core cannot
promote it to a measured target. A confirmed target must instead carry a finite
right-handed project-space point in metres and explicit observed/fitted support
IDs.

`evaluate_tool(kMarkProtrusion, ...)` validates that the pinned target is
current before making an intent command eligible. It requests the first missing
face in the required sequence: first return, front, second return. It neither
creates a rib profile nor assumes equal/perpendicular returns. Stale or invalid
face evidence rejects the request without retargeting the parent.

## Contract links

- B-027 / TC-027: unsupported taps remain pending; the rib tool requests
  missing faces.
- D02 section 4 and D17 sections 4–5: selection is target identity plus
  revision; missing depth must not create an invented point.
- D16 sections 6–8: support provenance remains distinct from semantic intent;
  a revision mismatch requires confirmation through the command path.
