# B-010 evidence — synthetic normalized replay to provisional plan

Date: 2026-09-22

Branch: `hss/b010-vertical-slice`

Baseline: `f800ce4`

## Delivered host-only vertical slice

`hss::vertical_slice::build_provisional_plan` replays the owned B-008 record
format and forwards every accepted epoch, depth frame, and mesh event through
the unchanged `hss_api.h` C facade used by the Swift bridge. The facade remains
the ABI validation and synchronous-ownership boundary; it is stepped after
each submission so bounded ingress does not accumulate borrowed or unbounded
data. No existing ABI type, engine entry point, replay implementation, ingress
policy, durable storage, epoch coordinator, Swift file, or Xcode project file
changed.

The separate verification builder retains normalized source identity and
derives one outer ring from edges belonging to exactly one triangle in exactly
one live mesh. It requires one closed, degree-two, non-self-intersecting ring
in an explicitly accepted epoch, projects source vertices through the recorded
anchor and epoch transforms into the B-011 metre/right-handed floor basis, and
orients the ring counterclockwise. Signed area uses a translated local origin
and compensated summation. It does not quantize headings, impose right angles,
drop or simplify source boundary vertices, close missing edges, merge multiple
anchors, or manufacture hidden surfaces.
Missing mesh evidence, an unresolved epoch, multiple live anchors,
open/ambiguous topology, non-planar/nonfinite output, or configured resource
caps produce no snapshot.

Every successful product is hard-labelled
`kind=synthetic_host_provisional_plan`, `source_is_synthetic=true`, and
`quality_state=provisional`. It cannot be represented as a production scanner
snapshot. The deterministic fixture is a six-sided oblique synthetic floor
mesh with preserved Float32-derived coordinates and area
`13.155000145435331 m2`; its JSON also records capture ID, epoch, anchor ID,
generation, revision, captured-format provenance, source vertex indices, the
C-ABI forwarding count, and `hidden_geometry_synthesized=false`.

## Rejection and bounded-behavior coverage

`hss_provisional_plan_test` covers two identical replays, the independent JSON
oracle, metre/right-handed and finite output, source identity, arbitrary-angle
preservation, and three-event C-facade traversal. Negative cases cover event
sequence disorder, an undeclared epoch, incompatible serialized provenance,
an explicitly unresolved epoch, missing mesh evidence, a boundary-vertex cap,
and nonfinite normalized mesh input. Failed builds return an empty snapshot;
there is no partial plan to mislabel as accepted geometry.

## Contract gaps kept explicit

ABI v1 `HSSMeshEvent` has no mesh generation, monotonic timestamp, provenance,
normal, classification, or local-bounds field. `HSSFrame` cannot carry the
normalized RGB layout, crop metadata, or validity/fusion/preview masks. The
verification module therefore forwards every field the existing C boundary
can express and carries the complete normalized event in its owned sidecar;
plan derivation uses that owned source only after C-facade admission. This is
not a full-fidelity ABI round trip, and the missing fields are not silently
discarded or used to justify an ABI change here.
Normalized replay v1.1 also carries no project ID, so the ephemeral facade used
for admission keeps its config project ID all-zero rather than conflating the
capture ID with project identity; no project identity is emitted by this slice.
The B-008 format currently has only `Provenance::kCaptured`, including for its
synthetic fixtures, so the stronger output-level `source_is_synthetic=true`
label is mandatory and prevents this fixture from becoming capture evidence.

The existing facade deliberately emits an immutable zero-geometry
`HSSSnapshot`, and the public ABI exposes no plan-result type. Consequently,
the B-010 product is a portable C++ verification snapshot after C-boundary
admission, not a Swift-consumable production snapshot. Connecting a real plan
backend to `hss_engine_acquire_snapshot` requires a separately reviewed ABI-
compatible engine implementation task; this change does not pretend that gap
is closed.

## Not run / unavailable physical criteria

No iPhone or simulator build, ARKit/RoomPlan session, sensor-buffer replay,
actual capture, Swift bridge invocation, protected-data save/reopen,
interruption recovery, thermal/endurance run, export, cloud call, or physical
metrology was run. Actual capture-to-plan acceptance still requires all of the
following on declared hardware: calibrated depth/camera convention and
orientation checks; accepted epoch/relocalization behavior; an irregular room
with independently measured oblique endpoints and instrument uncertainty;
narrow-feature completeness; deterministic save/reopen; interruption and
resource-pressure recovery; and a Swift-visible engine snapshot whose source
records and plan lineage agree. None of those results can be inferred from
this host/synthetic slice.
