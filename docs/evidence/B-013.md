# B-013 bounded frame/event ingress evidence

Scope: portable C++ ingress only for REQ-008 / REQ-038 and TC-013. This does
not claim ARKit, Metal fusion, replay/storage, or physical-device validation.

## Contract exercised

- `HSSConfig.max_pending_frames` limits queued frames. A full frame mailbox
  returns `HSS_OK`, increments `dropped_frames`, and makes no input copy.
- `HSSConfig.max_working_bytes` is checked before any payload-vector allocation.
  A structural event or command that cannot fit returns `HSS_RESOURCE_LIMIT`;
  it is not best-effort dropped.
- A separate finite 128-event limit prevents zero-byte epochs/removals from
  forming an unbounded queue. Events are one FIFO, so epoch, replacement and
  removal identities retain their capture/anchor IDs, revisions, sequences and
  order until `hss_engine_step` drains them.
- Queued metadata has null C pointers. Only owned vectors retain input bytes;
  callers may reuse input buffers when the C function returns.
