# B-003 evidence — capture capability/readiness gate

## Delivered

`HSSApp/ReadinessView.swift` now exposes a dependency-injected, read-only
capture readiness gate. It checks camera permission state, ARKit world-tracking
support plus `sceneDepth` and mesh-reconstruction support, usable local storage,
and an initial tracking state. Every failing requirement produces a specific
blocked-condition message; the default system implementation reports tracking
as not established because this packet deliberately does not create an
`ARSession`.

The screen never presents capture as available while any condition is blocked.
It does not request permission, initialize an AR session, start capture, create
geometry, invoke RoomPlan, or claim LiDAR correctness. `tests/HSSAppTests.swift`
uses a stub platform dependency and covers the ready, denied-permission,
unsupported-feature, unavailable-storage, and unestablished-tracking outcomes
without device access.
