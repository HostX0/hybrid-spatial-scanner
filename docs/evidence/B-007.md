## Delivered contract

`hss::storage::DurableSourceStore` is a portable C++ transaction core with a
small `FileSystem` boundary and a POSIX-backed `NativeFileSystem`. It introduces
no C ABI entry point, does not change `include/hss/hss_api.h`, and does not
change a JSON schema, AR session owner, depth adapter, or mesh adapter.

The only record kinds are selected `depth` and `mesh` source records, and the
only accepted provenance is `captured`. Inputs own copied byte vectors, so no
ARKit, Metal, or caller pointer is retained. A zero-length mesh record is
reserved for an already-accepted mesh removal; zero-length depth records and
unknown/generated provenance are rejected. The manifest carries capture UUID,
mesh-anchor UUID, session epoch, event sequence, monotonic time, source
revision, payload version, length, SHA-256, and a generated relative chunk path.
The replay order is strictly increasing event sequence and is validated on
recovery.

Each checkpoint writes a content-addressed immutable source chunk to a
temporary file, flushes/closes it, atomically replaces the chunk, reads it back,
and validates its SHA-256 and length. Only then does it write, checksum, and
validate a pending manifest. The active manifest is replaced last. Before that
replacement, the previous validated manifest is durably preserved. Recovery
accepts the active manifest only when every referenced chunk validates; otherwise
it uses the prior validated manifest. Temporary/orphan assets are never a
revision. After a successful checkpoint, garbage collection removes chunks not
reachable from either retained valid manifest, which bounds physical retention to
the current/previous bounded windows instead of merely bounding an in-memory
index.

The initial retention defaults are 128 depth records, 256 mesh records, 256 MiB
total retained payload, and 256 MiB per chunk. Callers can supply tighter
limits. The store rejects a checkpoint that would exceed those limits; it does
not silently evict selected source evidence. Any future eviction/pinning policy
must explicitly prove it does not remove the only source needed for refinement.
The store does not
serialize a metric scene, inferred surface, generated geometry, image, or cloud
state as captured source.

## Focused replay-review repair

After rebase onto `main` `ca6fd2e`, the focused B-007 follow-up repaired three
storage replay defects without changing the ABI, schemas, replay/engine code,
Swift code, or Xcode targets.

- Native reads now inspect file size before allocating. Manifests are limited to
  16 MiB; manifest-referenced chunks are read with their declared length, which
  has already been checked against the configured 256 MiB maximum. Oversized,
  unreadable, or allocation-failed candidates are rejected, and recovery uses a
  valid previous manifest when available.
- Retention is now non-evicting. A candidate that exceeds record or byte limits
  returns `kResourceLimit` before any chunk or manifest write, leaving both
  active and previous revisions unchanged. This deliberately replaces the
  earlier silent oldest-source eviction policy.
- Every mesh record, including an empty removal event, requires a nonzero stable
  anchor UUID. Write validation and manifest/recovery metadata validation reject
  an all-zero mesh identity; valid removals retain their UUID and zero payload.

The added regressions use sparse 16 MiB-plus manifests and 300 MiB chunks, so
the bounded native read path must reject them before allocation. They also cover
the non-evicting `kResourceLimit` path, valid removal round trip, and zero-anchor
write/recovery metadata rejection.

## Remaining validation

This is a host/POSIX transaction oracle, not an iOS protected-data guarantee.
No Xcode target changed, so no iOS build/test was required for this change.
Before shipping the native adapter, test iPhone backgrounding, lock/protected
data transitions, process termination at every filesystem boundary, low disk,
permission changes, and migration. The B-005 depth and B-006 mesh adapters
remain responsible for proving their platform buffer layouts and selected-source
semantics on physical hardware; this storage layer intentionally does not turn
their synthetic host payloads into sensor/metrology evidence.
