# B-028 — Calibrated, rotation-safe overlays

## Scope

This slice adds a pure Swift mapping from an observed scene-depth pixel through
its declared depth crop and captured-image coordinates, then through the
matching ARKit display transform into the current screen viewport. It is a
presentation mapping only: it does not unproject depth, raycast, fit surfaces,
change source data, or create project geometry.

`ARFrameCalibratedOverlayAdapter` is a conditional iOS boundary that snapshots
the `ARFrame` camera calibration, `sceneDepth.depthMap` dimensions, and
`displayTransform(for:viewportSize:)` for one frame and one viewport. Existing
`ARFrameSceneDepthAdapter` remains the owner of scene-depth ingestion; this
packet deliberately does not alter the AR session, target tools, command path,
or renderer.

## Contract behavior

- Calibration remains in unrotated captured-image/depth-crop pixels. The
  display transform is only applied after crop-to-image normalization; it is
  never used as camera/depth calibration.
- The transform carries its exact frame identity, viewport dimensions,
  viewport generation, and presentation orientation. A size/generation change
  or rotation therefore returns a hidden overlay until a new ARKit transform is
  supplied for the new viewport.
- A different epoch, frame-transform mismatch, invalid/nonfinite calibration
  or transform, stale timestamp, invalid depth pixel, and offscreen result are
  all hidden with an explicit rejection reason. The caller must retain a
  pending target rather than replacing it with an estimated screen point.
- This preserves B-027's rule that an unsupported no-depth tap has no invented
  project-space coordinate or support. B-028 only maps an already observed
  depth-pixel reference for presentation.

Executed from the B-028 worktree with Apple Swift 6.4:

```sh
swiftc -parse HSSApp/Overlay/CalibratedOverlayMapper.swift \
  HSSApp/Overlay/ARFrameCalibratedOverlayAdapter.swift \
  tests/CalibratedOverlayMapperTests.swift
swiftc -typecheck HSSApp/Overlay/CalibratedOverlayMapper.swift
swiftc -D OVERLAY_STANDALONE HSSApp/Overlay/CalibratedOverlayMapper.swift \
  tests/CalibratedOverlayMapperTests.swift \
  -o work/b028-check/calibrated-overlay-tests
work/b028-check/calibrated-overlay-tests
```

All commands exited 0. The standalone focused checks cover explicit depth-crop
mapping, hiding an old transform after a portrait-to-landscape viewport change,
and hiding cross-epoch presentation.

An XCTest target was not executed: this host Swift installation cannot resolve
the `XCTest` module outside the iOS app test target, and B-028 does not modify
the Xcode project to register the new test/source files. The committed XCTest
case is ready for registration by the owning target integration change.

## Limits and required device validation

No iPhone, ARKit session, display-transform registration, renderer, camera
preview, rotation UI, relocalization, scene-depth buffer, or physical metrology
test ran here. In particular, the exact platform orientation/display-transform
semantics and timing must be verified on supported devices in portrait and both
landscapes, across rotation, tracking loss/relocalization, cropped/off-axis
depth, and stale-frame suppression. This host result is numerical/API-shape
evidence only and does not claim ARKit or physical overlay accuracy.
