# B-011 evidence — coordinate and floor basis

## Delivered

`SpatialCore/include/hss/coordinate_basis.hpp` and its implementation establish
the portable core conventions used by the existing C facade: canonical physical
values are metres; project space is right-handed with `+Y` up; transforms are
column-major rigid `4x4` matrices; and the default floor frame is
`O=(0,0,0)`, `U=(1,0,0)`, `V=(0,0,-1)`, `N=(0,1,0)`.  Floor projection is
`(dot(P-O,U), dot(P-O,V))` and validates orthonormality plus `U cross V=N`.

Axial depth projection returns `(x,-y,-z)` in the documented AR-camera
convention from sensor-grid intrinsics and metres.  A column-major point
transform is provided separately.  Presentation orientation is explicitly a
pixel mapping to the recorded sensor grid; it neither changes intrinsics nor
rotates a pose.  Its four deterministic mappings cover landscape and portrait
forms, and a caller must apply it at most once.

The facade now delegates frame, epoch, and mesh transform validation to the
same core rigid-transform implementation.  It rejects nonfinite values,
non-homogeneous final rows, scale, non-orthogonality, and reflections with
`HSS_INVALID_COORDINATE_FRAME`.  It does not infer an epoch relationship from
a numerically valid or equal matrix: `relationship_state` remains an explicit
adapter-supplied semantic value, and this zero-geometry facade emits no
cross-epoch geometry.
