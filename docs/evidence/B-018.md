## Delivered standalone model and validator

`hss::rib` defines one bounded, directed six-vertex/five-segment chain with
the required semantic order: approach, first return, front, second return and
continuation. Every vertex retains source-provenance identifiers. Every
segment retains parent/replacement lineage, supporting-surface identifiers,
source-provenance identifiers and an explicit topology-protection flag.

`validate` accepts only a complete connected chain with all six distinct
vertices, all five roles in order, evidence on every vertex and segment, and
protection on every segment. It rejects invalid identities and lineage,
missing evidence, missing/reordered segments, unknown or ambiguous endpoint
use, nonfinite/out-of-range coordinates, duplicate vertices, short segments,
straight role-labelled broad-wall substitutions and non-adjacent segment
intersections. Failure is atomic. Success returns an exact copy; it never
reorders, inserts, removes, merges, simplifies or edits geometry.

`validate_update` first validates both snapshots, then requires the same
feature identity, an increasing revision, and either stable entity identities
or explicit candidate-to-predecessor lineage at each corresponding vertex and
semantic segment. Coordinates may refine. No equality of returns, fixed
width/depth, parallelism, orthogonality, winding or symmetry is required.

The authored fixture uses oblique approach/continuation directions, unequal
returns and a nonorthogonal front. It is synthetic mathematical input, not a
sensor observation. Tests preserve that geometry exactly, accept a
lineage-linked refinement, and reject missing front/return evidence,
unprotected topology, missing predecessor lineage, ambiguity,
self-intersection and a broad straight-wall replacement.

## Scope and limitations

This is an additive portable C++20 module and additive CMake target/test. It
does not edit or integrate the existing engine, boundary graph, C ABI, schema,
Swift/Xcode code, simplifier, solver, save/reopen path or exporter. It validates
submitted evidence and lineage but does not produce either from sensor input.
It does not classify a chain as a physical protrusion or recess and does not
infer unobserved surfaces.

No iPhone/simulator build, ARKit/RoomPlan session, capture/replay, physical
metrology, performance/thermal measurement, save/reopen or export test ran.
Passing the synthetic host checks makes no claim about feature detectability,
physical dimensions, sensor accuracy or production scanner completion. Later
graph-update and simplification integration must map accepted graph entities
into this model without dropping source evidence or protection.
