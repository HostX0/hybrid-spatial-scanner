# B-020 evidence — shelf/structural surface separation policy

Date: 2026-09-22

Branch: `hss/b020-shelf-separation`

Baseline: `f2b6642`

## Delivered standalone policy module

`hss::surface_policy::separate` is a standalone C++20 policy module over
already-supported metric surface evidence. It does not fit, merge, synthesize,
move, or relabel geometry. Successful decisions copy every submitted plane,
mesh reference, surface identity, support identity, geometry origin, and
evidence role exactly. Semantic class and semantic origin remain separate from
the metric evidence role.

Structural evidence is routed to the structural layer. Object evidence is
routed to furniture or overhead presentation; a shelf label does not turn an
object surface into structural geometry. Contradictory semantic/evidence roles
and mixed metric roles within one entity are rejected as ambiguous rather than
silently reclassified.

For object evidence, rear and underside faces remain explicitly unknown unless
the request contains a supported surface for that face. Inferred and unknown
geometry origins are not accepted as trusted surface evidence. Nearby parallel
planes are retained as separate surfaces and entities with their independent
support IDs; the policy has no merge operation.

A fixed obstruction is emitted only when all three gates are present: an
explicit fixed planning classification, supported floor contact, and the
explicit `net_fixed_obstructions` area policy. Floor contact alone, a semantic
label alone, a fixed classification without floor support, or a
floor-footprint-preserving policy leaves the object outside the fixed
obstruction layer. This is a planning classification, not a structural or
load-bearing claim.

The input is bounded by caller and hard caps. It validates canonical UUIDs,
supported enum values, evidence support, opaque geometry references, finite
unit planes, kind/plane consistency, duplicate identities, and entity role
consistency before constructing any decision. Every nonfinite, unsupported,
resource-limited, missing-evidence, or ambiguous failure returns an empty
decision optional.

## Focused synthetic coverage

`fixtures/surface_policy/shelf_parallel_wall.csv` is explicitly synthetic. It
contains an oblique fitted wall plane and a separately supported observed shelf
front 0.08 m away with the same unit normal, plus a captured shelf-top mesh
reference. The test verifies that both close parallel surfaces remain distinct,
the shelf mesh reference persists, no floor obstruction is created, and the
unseen rear and underside stay unknown. The separation is fixture arithmetic,
not a measured feature-resolution result.

`hss_surface_separation_test` additionally covers:

- semantic labels that conflict with metric evidence roles;
- unknown semantics preserving object evidence without promoting it;
- an observed underside clearing only that face's unknown state;
- rejection of an inferred hidden rear surface;
- all fixed-obstruction gate combinations and ambiguous floor support;
- nonfinite and non-unit planes, unsupported enum values, missing support,
  duplicate IDs, mixed roles, undeclared policy/tolerance, and resource caps;
- atomic failure with no partial decision for every rejection path.

## Scope and tests not run

The new library and test target are additive. The module is not wired into
`SpatialCore`, `hss_engine`, B-021 ceiling work, the public C ABI, schemas,
Swift, Xcode, replay, persistence, export, or an area calculator. No existing
module or ABI layout was changed.

No iPhone/simulator build, ARKit/RoomPlan session, physical shelf capture,
hidden-face observation, metrology, sensor replay, performance/thermal run,
save/reopen, area subtraction, or export interoperability test ran. Passing
synthetic host policy checks makes no claim about sensor accuracy, minimum
resolvable separation, physical completeness, structural function, or
production scanner completion. Integration must supply accepted metric
evidence and floor-contact provenance without weakening these gates.
