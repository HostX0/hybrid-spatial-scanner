## Delivered portable module

`hss::dynamic_provenance::apply_exclusion` consumes the typed
`hss::scene_editing::DynamicExclusion` produced by I-EDIT and constructs a
separate per-triangle mask. It accepts the captured mesh by const reference and
has no API that returns replacement vertices, triangles or structured proxies.
The caller's raw captured mesh therefore remains the retained source for
rebuild, inspection and captured export.

A pending exclusion is only an audit boundary. With no independently verified
capture evidence, the result is `kNoVerifiedEffect`, every mask byte is zero and
the audit records zero masked triangles. The module does not treat a semantic
label, user command or audit marker as proof that geometry was dynamic.

A triangle is masked only when all of its captured support records match a
verified evidence record by exclusion command, project, source identity,
capture identity, session epoch and event sequence. The captured sequence must
be within the command's inclusive range. Both the triangle and verification
bounds must be inside the requested region. Partial support leaves the whole
triangle visible. Accepted output records the exact source indices and selected
evidence IDs behind every masked triangle.

Evidence is limited to typed temporal-depth-change or tracked multi-frame-motion
records. Collection sizes, total triangle provenance references and project
coordinates have caller limits and compile-time ceilings. Invalid options,
exclusion bounds, meshes, provenance, evidence identities, sequence intervals,
capture/epoch links and coordinates fail atomically without a partial layer.
Duplicate source and evidence identities are rejected, as is more than one
linked verification record for the same captured source. Ordered source-key
maps make evidence lookup bounded and ensure evidence input order cannot alter
the result.

## Focused synthetic coverage

`hss_dynamic_provenance_test` uses authored geometry and provenance only; it is
not a phone capture or physical-accuracy result. The positive case verifies one
fully supported triangle is masked while a partially supported triangle, a
spatially outside triangle and an out-of-sequence triangle remain visible. It
also verifies the input mesh is unchanged and reversed evidence input produces
the same mask and audit trace.

Negative cases cover an audit marker with no evidence, partial evidence,
evidence for another command, sequence/bounds outside the exclusion,
capture/epoch mismatch, malformed intervals, nonfinite geometry, noncanonical
source references, duplicate evidence, invalid evidence kind, invalid options
and collection limits. Every validation failure returns no mask layer.

## Contract impact and unverified layers

This change adds a portable C++ module and test target. The public C ABI and
JSON schemas are unchanged. It does not edit or integrate `hss_engine`, live
reconstruction, scene editing, project storage, Swift/UI or object capture.
The scene-edit adapter continues returning pending exclusions without claiming
a geometry mutation; an integration owner must explicitly pass its typed record
and retained verified source evidence to this module.

No full-suite rerun was performed because the module is isolated and its only
build dependency (`hss_scene_editing`) built successfully in the focused
sanitizer target. No simulator/iPhone test, ARKit motion verification, dynamic
person/curtain/screen capture, renderer integration, save/reopen replay, OBJ
export, performance, thermal or physical metrology test ran. B-035 product and
physical acceptance remain unverified until those native integrations and
device cases are completed.
