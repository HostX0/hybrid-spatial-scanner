## Delivered portable semantic layer

`hss::plan_semantics::assemble` consumes caller-submitted plan fragments and
the existing B-017 intersection, B-019 validated-ring/area, and B-021 ceiling
classification contracts. It copies accepted geometry and lineage; it never
connects, closes, extends, projects, hulls, snaps, or fills geometry.

Floor footprint, architectural cut, and reflected-ceiling views are distinct.
Floor/cut views retain the selected height, sampling band, and floor-reference
state. Every supported fragment must carry source revision, support IDs, a
metric height range inside that band, and valid source-specific evidence.
B-017 source IDs cannot disappear between an intersection proposal and its
plan fragment. Area-ring provenance must match the same scene revision and be
traceable to retained fragment support.

A numeric B-019 area is exposed only for a confirmed floor frame, a closed
accepted boundary, metric (observed/fitted/user-measured) origins, and ready
ring quality. Open topology returns a provisional null area. Unknown floor or
boundary evidence, inferred geometry, and unsupported inputs remain explicit
issues with null area. Reflected-ceiling area is explicitly not applicable;
B-021 local patch heights and unknown/no-depth regions remain separate.
Contradictory topology declarations, cross-revision lineage, missing source
IDs, malformed height policy, and nonfinite geometry fail atomically.

No public C ABI, schema, live reconstruction, storage, UI, or exporter changed.

## Scope and unverified layers

The tests use authored synthetic geometry and provenance. They verify semantic
separation and deterministic validity decisions, not scanner accuracy. The
module is not connected to `hss_engine`, Swift/Xcode, save/reopen, rendering,
annotations, or frozen exporters. No simulator/iPhone build, real capture,
physical metrology, performance/thermal test, or CAD-consumer test ran.

Integration must map one frozen scene revision into these inputs without
inventing missing fragments and must preserve the resulting issues through
storage, review UI, and export metadata. Physical acceptance still depends on
the original B-017/B-019/B-021 gates and TC-031 device evidence.
