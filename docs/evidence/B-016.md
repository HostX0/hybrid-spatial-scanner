## Delivered portable boundary module

`hss::boundary::validate` is a standalone C++20 validator for one directed,
ordered outer boundary and zero or more directed, ordered holes. The caller
declares the near-zero edge threshold, geometric comparison epsilon, coordinate
extent, entity caps, lineage caps and pair-test budget. Hard upper bounds also
limit nodes, edges, holes, lineage references and quadratic pair checks.

Nodes, edges and loops use canonical lowercase non-nil UUID strings. Nodes and
edges retain explicit parent/replacement lineage; edges also retain supporting
surface IDs, provenance support IDs and topology-protection state. A successful
result contains an exact copy of the submitted graph. The validator does not
reverse edges, invent closure, reorder loops, merge nodes/edges, simplify
collinear chains, create a convex hull or otherwise repair topology.

The outer loop must be closed, simple and counterclockwise. Holes must be
closed, simple, clockwise, strictly contained by the outer loop and mutually
disjoint. Validation rejects malformed/duplicate IDs, invalid references,
self/conflicting lineage, nonfinite or out-of-range coordinates, duplicate
vertices, zero/near-zero edges, repeated/unassigned edges, unused or shared
nodes, open/ambiguous chains, degenerate/wrong-winding loops,
self-intersection/backtracking/self-touching, outer-hole contact, outside holes
and overlapping/touching holes. Every failure returns an explicit status and an
empty accepted-graph optional.

The focused synthetic fixture retains a protected forward-collinear pair, the
0.50 m by 0.15 m concave rib chain, node and edge lineage/support fields, and a
detached clockwise hole. Additional programmatic cases exercise arbitrary
oblique angles and the rejection paths above. These are mathematical fixtures,
not sensor observations.

## Scope and limitations

This task adds no robust fitting, provisional-plan, engine, C ABI, schema,
Swift/Xcode, recovery, import or resource-module integration. It does not
compute or publish area and does not triangulate. The translated compensated
signed-area calculation is used only to validate nondegeneracy and winding.
The module uses bounded long-double host predicates with caller-declared metric
tolerances; it is not a claim of exact arbitrary-precision computational
geometry.

No iPhone/simulator build, ARKit/RoomPlan session, capture/replay, physical
metrology, performance/thermal measurement, save/reopen or export test ran.
Passing the synthetic host checks makes no claim about physical geometry,
sensor accuracy or production scanner completion. A later integration must map
accepted scene entities into this contract without discarding source evidence
or weakening topology protection.
